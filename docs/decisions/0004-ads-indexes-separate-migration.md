# ADR 0004: индексы `ads` отдельной миграцией

Статус: принято, пересмотреть на Этапе 5.

## Контекст

README требует индексы `ads(created_at)` и `ads(category_id, city_id)`.
Но матчер получает объявления из события `ad.created` и не читает
таблицу `ads` по этим колонкам. Ingestion — поток вставок, а каждый
индекс замедляет вставку.

## Решение

Индексы вынесены в отдельную миграцию `002_add_ads_indexes.sql`,
таблица создаётся в `001`. Оба индекса пока оставлены, как в README и
чеклисте Notion.

## Почему

- `created_at` пригодится для reconcile-прохода (см. «Известные
  ограничения» в README).
- У `(category_id, city_id)` сейчас нет потребителя запросов. Оставлен
  временно, это кандидат на удаление.
- Отдельная миграция откатывается без потери таблицы.

## Последствия

- `make migrate-down` откатывает только последнюю миграцию. Включать и
  выключать индексы «одной командой» можно только пока `002` последняя.
  Позже убрать индексы можно новой миграцией вперёд.
- Для замеров на Этапе 5 индексы переключаются вручную через SQL.
- Замерить пропускную способность вставки с индексами и без.
