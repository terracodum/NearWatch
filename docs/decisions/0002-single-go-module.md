# ADR 0002: один Go-модуль вместо `go.work` и `services/`

Статус: принято (Этап 1).

## Контекст

README и план в Notion предполагали монорепу через `go.work`, у каждого
сервиса своя папка `services/<name>/` и свой `go.mod`.

## Решение

Один корневой `go.mod` (`github.com/terracodum/nearwatch`). Код сервисов:
`cmd/<service>/` и `internal/<service>/`.

## Почему

`go.work` не давал выгоды: разработчик один, зависимости общие, а
изоляция версий между сервисами не нужна. Лишние `go.mod` добавляют
шагов (синхронизация, `go work sync`) без пользы.

## Последствия

- Все сервисы делят один набор зависимостей и версию Go.
- Dockerfile каждого сервиса собирает из корня модуля.
- Если сервисам понадобятся независимые зависимости, модуль придётся
  делить: тогда вернуться к `go.work` и новому ADR.
- README (дерево проекта, раздел «Технологии», строка про `go.work`,
  таблица решений «Монорепа без submodules») ещё описывает старую
  структуру и требует правки.
