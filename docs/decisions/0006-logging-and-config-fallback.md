# ADR 0006: логирование и поведение конфига

Статус: принято (Этап 1).

## Решения

**Конфиг.**

- Неизвестный `LOG_LEVEL` молча превращается в `info`: уровень логов не
  влияет на работу, ронять из-за него старт не нужно.
- Кривой `SHUTDOWN_TIMEOUT` — ошибка старта: он меняет поведение при
  остановке, молчаливый дефолт скрыл бы ошибку.
- Дефолт именно `info`, не `warn`: `LOG_LEVEL` — порог, `warn` скрыл бы
  `info`, и при проблеме логов стало бы меньше.
- Запланировано: предупреждение в лог «неизвестный LOG_LEVEL, использую
  info». Пока логгер создаётся после разбора уровня, подумать, как это
  сообщить.

**Логирование.**

- Запросы логирует одна HTTP-обёртка (метод, путь, статус, длительность).
- Руками: события `main` (старт, сигнал, shutdown), неожиданные ошибки
  (500) в хендлере.
- В `domain` логов нет.
- Ошибку логируют один раз, там, где она обработана. Слои ниже
  оборачивают её (`fmt.Errorf("...: %w", err)`) и возвращают.
- Логгер передаётся через конструкторы, не глобально.

## Последствия

- 400 от валидации в логи приложения не пишутся, их видно по статусу в
  access-логе.
- Логи в JSON-режиме, с полями вместо склеенного текста.
