# ADR 0005: `Ad` создаётся только через `NewAd`

Статус: принято (Этап 1).

## Контекст

Исходный план: структура `Ad` с методом `Validate()`, который надо не
забыть вызвать. Появится второй вход (gRPC на Этапе 2), и забытый вызов
пропустит невалидное объявление.

## Решение

- Поля `Ad` неэкспортируемые, чтение через геттеры.
- Создание нового объекта: `NewAd(NewAdParams) (Ad, error)`, внутри все
  проверки. `NewAdParams` — структура с экспортируемыми полями, в неё
  хендлер декодирует JSON.
- Восстановление из БД: отдельная функция `RestoreAd`, **не пишется,
  пока нет первого чтения** `ads`.

## Правила проверки

- `title`: не пустой после `TrimSpace`, не больше 200 **символов**
  (`utf8.RuneCountInString`, не `len`).
- `description`: не больше 4000 символов.
- `price >= 0`.
- `category_id > 0`, `city_id > 0` (допущение: id с единицы).
- `lat` в `[-90, 90]`, `lon` в `[-180, 180]`, заданы обе или ни одной
  (`*float64`, `nil` = координат нет).

## Последствия

- Граница защиты — пакет `domain`. `domain.Ad{}` (нулевое значение)
  снаружи получить можно, передавать такой объект дальше нельзя.
- Нужны геттеры для репозитория и отдельная структура запроса в
  хендлере.
- Тесты table-driven на `NewAd`.

## Открытые вопросы

- Ошибка валидации: переменная и `errors.Is` или собственный тип.
  Для Этапа 1 достаточно переменной.
- Разрешено ли пустое `description`.
